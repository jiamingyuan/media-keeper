## 决定

- 替代 V0.1 的整仓库 Skill 布局：应用放 `apps/api` 与 `apps/web`（初期为空，用户后续授权后实现远程前端）；采集放 `skills/media-keeper`；共享规则与数据库操作放 `packages/core`、`packages/db`；schema 与迁移放 `database`。只保留根目录一份 npm 锁文件。来源：用户结构调整要求与附图。
- 采集流程保留全文确认、飞书副本及恢复行为；SQL 访问共用 db 包，Markdown 比较留在 Skill；API 不要求飞书配置。这样采集可以独立于查询服务运行。
- API 使用独立 SELECT 账号与只读快照事务，采集账号沿用 SELECT/INSERT/UPDATE；配置分别加载，口令文件在被忽略的 runtime 中。来源：附图的权限与配置边界；依据当前实现。
- 当前实现的筛选语义：title、source、author 包含匹配，source_type 精确匹配，多条件 AND；source_created_at 为 YYYY-MM-DD，按 Asia/Shanghai 自然日转为 UTC 左闭右开范围。这些具体匹配与时区取值由 Agent 实现并在对话中说明，用户原话只指定了字段和“按天”，未单独明确指定时区或匹配算法。
- 增加分页、稳定排序、详情、类型列表与健康检查，统一 HTTP 输入校验和错误响应；具体接口参数以 [README](../../README.md) 为准，不在这里复写完整契约。
- `tools/build-skill.mjs` 将共享 core/db 代码打包到独立 Skill 产物，运行依赖由产物 package.json 声明；不要求 Agent 安装或启动查询后端。
- 用户明确要求默认不生成额外工作区梳理文件：移走此前多建的 docs 与临时验证产物，以根目录 npm 命令替代额外 bin。此次用户明确要求建立 pjkp，使用每版本一份 iteration.md 的新版记忆结构；不新增旧式计划、执行、验收事务文件。
