## 目标与来源

2026-10-24 用户要求 Bilibili 来源视频统一通过匿名音轨生成 abstract，并为节省空间删除音频和临时文件；2026-10-26 用户要求“帮我push github吧，然后命名V0.4”。本次基于 V0.3 提交 `b968b92134bf8c7d4fb2cf332447e84b54b8349f`，收录其后的音频采集改动，归档引用为 main / V0.4。

## 实际变化

- 新增 `skills/media-keeper/scripts/bilibili.py`：按 BV/av/短链接解析视频和分 P，通过匿名 pagelist/playurl 请求获取最低带宽独立音轨，使用主备地址和有限刷新，不依赖网页、字幕登录态或 Cookie；校验下载字节数、完整时长，拒绝试看或无可用话语的音频。
- 本机 faster-whisper 完整转写，由调用 Skill 的 Agent 生成不超过 400 个 Unicode 字符的中文摘要，沿用原查重和收藏流程；只总结音频信息，不根据简介或未知画面编造。独立 Python 依赖锁定于 audio-requirements.txt。
- 音频转写后立即删除；总结/保存结束使用 cleanup 清理该系统临时任务目录中的转写、元数据和临时入库材料。失败或可处理的中断会清理任务；清理失败返回明确错误，SIGKILL/断电需恢复后按原目录清理。模型、运行环境、用户文件及飞书恢复状态保留。
- 独立 Skill 构建包含音频脚本、依赖清单及使用规则；新增音频单元测试和 test:audio 命令。源码各 workspace、内部依赖、锁文件、Skill 元数据、Docker 标签声明统一至 0.4.0。
- 本地全局 Skill 同步 0.4.0，复用已有 Node/Python 依赖、模型、数据库配置和飞书身份；未新增收藏。
