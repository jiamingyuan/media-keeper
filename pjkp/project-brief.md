# media-keeper 项目简介

## 项目介绍

### 项目定位

帮助用户收藏资料，并先通过中文摘要判断是否需要阅读全文。当前由采集 Skill、只读查询 API 和接入 my-dashboard 的 Media 前端组成；API 与远程静态资源在独立 Nginx + Node 容器内运行，采集 Skill 全局安装并独立运行；项目由 docs-keeper 重命名而来。

### 项目概要

Agent 取得并阅读完整资料后生成最多 400 个 Unicode 字符的摘要，Skill 校验元数据、查重并保存到 MySQL `agent.useful_docs`。数据库存摘要和元数据，全文入口指向原文；原链接不可用但已有全文时，通过飞书 CLI 创建并回读副本，记录状态以供失败恢复。摘要由调用 Skill 的模型生成，程序未内置模型 API。

NestJS 后端读取同一张表，提供列表、详情、来源类型与健康检查。支持标题、来源、作者包含匹配，类型精确匹配，原文创建时间按日筛选，附分页和排序。用户已明确前端预期融入 my-dashboard，并完成其 Figma 中的预期样式：总览暂不接入，工具页采用类型图标导航、关键词与发布日期预设筛选，以及无内嵌底色的完整正文摘要；有 copied_lark_link 的条目在标题后显示飞书转存标签。来源与作者暂不提供 UI 筛选。用户随后授权前端开发：React + Vite 远程模块已通过 Module Federation 接入 my-dashboard；API 已支持 published 日期预设和类型计数，标题继续采用包含匹配。

### 项目价值

预期降低资料重读与检索成本；目前已验证具体程序行为，尚无实际使用收益评估。

### 长期愿景

将采集能力和浏览器端查询组织成同一产品，共用资料库。来源：2026-10-23 用户采纳的结构建议图及结构调整要求。原实现范围为后端、前端留空；2026-10-23 用户进一步要求在 my-dashboard 的 Figma 文件中呈现前端样式，暂时仅接入 media-keeper，并移除 AI 日报、背单词设计。用户随后要求开始开发并通过 Module Federation 接入；已在原 V0.2 中实现并接入本机网站，未指定新版本号。

## 项目功能

- 采集与收藏：支持 article、paper、podcast、video、tech_doc、project_repo 六种来源类型；其中 podcast 指小宇宙等音频播客，网站文章归 article；已有记录默认不覆盖，明确更新才修改。
- 全文入口：优先原链接，必要时飞书副本与失败恢复；不以抓取片段冒充全文。HTML 提取器不直接处理需登录页面、PDF、网页 JS 或视频转写；Bilibili 投稿视频由独立音频脚本免登录获取完整音轨、本机转写后生成摘要，任务媒体和临时转写在收尾清理。
- 查询：五字段组合筛选、分页、排序、详情；API 无写入接口，启动不要求飞书配置。
- 分发：开发时使用 npm workspaces；通过 build:skill 生成包含共享代码与运行依赖声明的独立 Skill 安装产物。
