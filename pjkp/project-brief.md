# media-keeper 项目简介

核对日期：2026-10-26。当前实现的技术与部署情况见 [architecture.md](architecture.md)。

## 项目定位与长期方向

帮助用户收藏网页、文章、论文、播客和视频，先通过读得懂的中文摘要了解内容，再选择是否阅读全文。摘要与来源信息便于检索，全文仍通过原文或必要的飞书副本访问。

采集与 Web 查询组成同一个资料产品，共用资料库；采集能力可以独立使用。来源：V0.1 的资料收藏定位、2026-10-23 用户采纳的结构建议与 Web 接入要求，以及 2026-10-26 对摘要可读性的反馈。网站端融入个人工作台 my-dashboard。预期降低资料重读与检索成本，尚无实际使用收益评估。

## 产品能力

- **采集与维护**：Agent 实际取得并阅读完整内容，生成摘要，整理标题、来源、类型、作者及原文时间，再由 Skill 校验、查重和保存；已有收藏默认不覆盖，明确更新时才修改。
- **全文入口**：通常优先使用可访问的原链接；原链接不可用但已有全文时，保存飞书全文副本与恢复状态。Loot Drop 创业报告以原文生成摘要，查证中国公司的中文名，命名为“{公司名称} Loot Drop 分析”，撰写有实质内容的飞书分析文档并保存双链接；完整转载或改写受相应内容/授权范围约束；来源为 Loot Drop，默认类型仍是 article，规则见 [转载规范](../skills/media-keeper/references/loot-drop.md)。摘要或抓取片段不能代替全文。
- **检索与阅读**：提供组合筛选、分页、排序和详情；工具页完整展示摘要、来源信息及全文入口。具体 API 与界面当前开放哪些条件见架构和 README。
- **视频音频**：Bilibili 投稿视频已有免登录完整音轨获取、本机转写、摘要及任务文件清理流程。其他视频和播客需要取得完整内容或逐字稿；当前没有通用 YouTube 音轨下载器，也没有自动查找官方播客 RSS 的实现。一次性外部实测见 V0.4。

## 来源类型与术语

`source_type` 按实际收藏对象区分：

| 值 | 含义 |
| --- | --- |
| `article` | 新闻、公众号及其他网站文章 |
| `paper` | 论文、预印本 |
| `podcast` | 音频播客节目或单集，例如小宇宙；节目简介和 show notes 不等于完整内容 |
| `video` | 视频，或用于理解该视频的完整字幕、音轨转写 |
| `tech_doc` | 技术文档、API 参考、使用/部署指南、技术规格和模型卡 |
| `project_repo` | 项目代码仓库及其整体项目入口页 |

用户在 2026-10-23 明确纠正：此前称作“博客”的类型实际是音频“播客”。网站文章归 `article`，模型卡与仓库中的具体技术文档归 `tech_doc`，收藏整个项目时才归 `project_repo`。这属于产品术语和分类定义；纠正经过与迁移结果见 [V0.2](V0.2/iteration.md)，采集时的具体判断见 [Skill](../skills/media-keeper/SKILL.md)。

## 能力边界

摘要由调用 Skill 的 Agent 生成，程序没有内置模型 API。HTML 提取器不执行网页 JavaScript，也不直接处理登录页面、PDF 或音视频转写；取得提取结果后仍需核对完整性。未知作者、原文时间可留空。当前资料库保存摘要、元数据与全文入口，不保存通用全文搜索索引。

接口与运行契约以 [README](../README.md) 为准；历史实现与验证分别见 [V0.1](V0.1/iteration.md)、[V0.2](V0.2/iteration.md)、[V0.3](V0.3/iteration.md)、[V0.4](V0.4/iteration.md)。
